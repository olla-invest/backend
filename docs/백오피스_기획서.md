# Olla 백오피스 기획서

- 문서 상태: 1차 기획 기준안
- 작성일: 2026-09-30
- 대상 시스템: Olla 관리자 백오피스
- 대상 독자: 기획, 디자인, 프론트엔드, 백엔드, QA, 운영, 보안

## 1. 문서 표기

요구사항의 출처와 확정 수준을 다음과 같이 구분한다.

- **[확정]** 요청문 또는 첨부 화면·주석에 명시된 내용
- **[제안]** 구현 일관성, 보안 또는 운영 안전성을 위해 이 문서에서 보완한 내용
- **[확인 필요]** 구현 전에 정책 결정이 필요한 내용

첨부 화면은 서비스 현황, 회원관리 목록, 회원 상세 및 운영 팝업의 기획 근거로 사용했다. 화면에 없는 세부 정책은 확정된 것으로 간주하지 않는다.

## 2. 배경과 목적

Olla 서비스의 사용자 현황과 주요 행동 지표를 한곳에서 확인하고, 운영자가 회원 상태·플랜·비밀번호 재설정·회원정보를 안전하게 관리할 수 있는 백오피스를 제공한다.

핵심 목표는 다음과 같다.

1. 가입부터 핵심 기능 사용, 탐색, 재방문까지 주요 서비스 지표를 기간별로 확인한다.
2. 회원을 조건별로 조회하고 운영에 필요한 조치를 수행한다.
3. 개인정보는 기본적으로 마스킹하고, 원문 열람과 운영 변경은 감사 가능한 형태로 기록한다.
4. 화면 조회와 CSV 반출에 동일한 데이터·보안 정책을 적용한다.

  - 개인정보 원문 열람
  - CSV 다운로드

  - 비밀번호 재설정
  - 회원정보 수정
  - 운영 감사 로그 조회
- **[확인 필요]** 관리자 역할 종류와 역할별 권한 조합

## 5. 공통 정책

### 5.1 날짜와 시간

- **[확정]** 일시 표기는 `yyyy-MM-dd HH:mm:ss` 형식을 사용한다.
- **[제안]** 저장·집계 기준 시간대는 Asia/Seoul로 통일하고 API에는 시간대가 포함된 ISO 8601 값을 사용한다.
- **[확인 필요]** 기간 필터의 시작일·종료일 포함 여부와 당일 실시간 데이터 포함 여부

### 5.2 목록 공통 동작

- 조회 조건 변경만으로 자동 조회할지, 조회 버튼을 둘지는 화면별로 일관되게 적용한다.
- 로딩, 빈 결과, 오류 상태를 구분해 표시한다.
- 페이지 이동 시 현재 검색·필터·정렬 조건을 유지한다.
- **[제안]** 브라우저 뒤로가기와 공유 가능한 조회 상태를 위해 조건을 URL query에 반영한다. 단, 개인정보 검색어는 URL에 노출하지 않는다.

### 5.3 CSV 공통 정책

- **[확정]** 서비스 현황과 회원 목록에서 CSV 다운로드를 제공한다.
- **[확정]** 회원 CSV의 개인정보는 화면과 동일하게 마스킹한다.
- **[제안]** 파일 인코딩은 UTF-8 BOM, 일시는 `yyyy-MM-dd HH:mm:ss`로 통일한다.
- **[제안]** 수식 주입을 막기 위해 `=`, `+`, `-`, `@`로 시작하는 셀을 안전하게 이스케이프한다.
- **[제안]** 다운로드 이력에 관리자, 시각, 화면, 조회 조건, 행 수, 성공 여부를 기록한다.
- **[확인 필요]** 다운로드 최대 행 수와 대용량 비동기 생성 여부

### 5.4 운영 감사 로그

다음 행위는 감사 로그 대상이다.

- 개인정보 마스킹 해제
- 회원정보 조회 **[확인 필요: 모든 상세 조회를 기록할지]**
- CSV 다운로드
- 플랜 변경
- 상태 변경
- 비밀번호 재설정 메일 발송
- 회원정보 수정

기본 필드는 다음과 같다.

| 필드 | 설명 |
|---|---|
| 발생 시각 | 서버가 기록한 수행 시각 |
| 관리자 | 관리자 고유 식별자와 표시 계정 |
| 대상 | 대상 회원 ID 또는 데이터 범위 |
| 행위 유형 | 마스킹 해제, 플랜 변경 등 |
| 변경 전/후 | 민감정보 원문을 제외한 변경 내용 |
| 사유 | 관리자가 입력한 사유 |
| 결과 | 성공 또는 실패와 실패 코드 |
| 요청 정보 | 필요 시 IP, User-Agent, 요청 ID |

- 개인정보 원문과 비밀번호·재설정 토큰은 로그에 저장하지 않는다.
- **[확인 필요]** 감사 로그 보관 기간, 열람 권한, 내보내기 정책

## 6. 서비스 현황

### 6.1 화면 목적

선택한 기간의 유입·가입, 핵심 기능 도달, 탐색 깊이, 재방문, 이용 환경을 한 화면에서 확인한다. 지표는 실시간 관제보다 서비스 사용 행태를 판단하는 운영 참고값에 초점을 둔다.

### 6.2 조회 조건

- **[확정]** 조회 기간을 선택한다.
- **[확정]** 선택 기간과 직전 동일 길이 기간을 비교해 증감 값을 표시한다.
- **[확정]** 화면 우측 상단에서 CSV를 다운로드한다.
- **[제안]** 기본 조회 기간은 최근 30일로 한다.
- **[확인 필요]** 선택 가능한 최대 기간, 빠른 기간 선택값, 데이터 갱신 주기

### 6.3 유입·가입

“처음 들어온 사람이 계정을 만들었는가”를 확인한다.

| 지표 | 표시 | 정의 초안 |
|---|---|---|
| 신규 사용자 | 명, 전주/직전 기간 대비 | 기간 내 최초 방문 사용자 수 |
| 가입 완료 | 명, 전주/직전 기간 대비 | 기간 내 가입을 완료한 사용자 수 |
| 랜딩 → 가입 전환율 | %, 직전 기간 대비 pp | 가입 완료 사용자 ÷ 랜딩 유입 사용자 × 100 |
| 가입경로 1위 | 경로, 경로별 비중 | 가입 완료 기준 가장 많은 LOCAL/KAKAO/NAVER 경로 |

- **[확인 필요]** 신규 사용자의 식별 기준(GA4 user, device, 내부 user ID)
- **[확인 필요]** 가입 전환율의 분모를 랜딩 방문자, 가입 시작자 중 무엇으로 볼지

### 6.4 핵심 기능 도달

“가입한 사용자가 핵심 기능에 도달했는가”를 확인한다.

| 지표 | 표시 | 정의 초안 |
|---|---|---|
| 핵심 기능 도달률 | % | 가입 후 7일 내 필터 또는 마켓뷰를 1회 이상 사용한 가입자 비율 |
| 첫 필터 적용까지 | 분·초 | 가입부터 첫 필터 적용까지 평균 또는 중앙값 |
| 세션당 필터 적용 | 회 | 필터 적용 횟수 ÷ 필터 사용 세션 수 |
| 기능별 사용률 | 막대와 % | 마켓뷰, 필터, 이슈 테마보드, 스마트서치 사용 비율 |
| 첫 사용까지 소요시간 분포 | 구간별 % | 가입 → 첫 필터 기준 10분 내, 1시간 내, 1일 내, 1일 이후, 미사용 |

- **[확정]** 첫 필터 적용 시간은 중앙값을 기준으로 한다는 화면 주석이 있다.
- **[확인 필요]** 핵심 기능의 정확한 목록과 이벤트명
- **[확인 필요]** 기능별 사용률의 분모를 활성 사용자, 세션, 가입자 중 무엇으로 볼지

### 6.5 탐색 깊이

“들어온 사람이 얼마나 깊이 탐색했는가”를 확인한다.

| 지표 | 표시 | 정의 초안 |
|---|---|---|
| 평균 참여 시간 | 분·초 | GA4 engagement time 기준 |
| 종목 상세 진입률 | % | 리스트 노출 후 종목 상세에 진입한 세션 또는 사용자 비율 |
| 검색 무매칭률 | %, 주의 표시 | 결과 0건 검색 횟수 ÷ 전체 검색 횟수 × 100 |
| 마켓뷰 뷰 전환 비중 | 히트맵/랭킹뷰 비중 | 기간 내 뷰 전환 결과 또는 체류 비중 |
| 결과 0건 검색어 | 순위, 검색어, 검색 수 | 결과가 없었던 검색어 상위 5개 |

- **[확정]** 결과 0건 검색어에서 “키워드 사전에 추가” 진입점을 제공한다.
- **[확인 필요]** 키워드 사전 관리가 이번 서비스 관리 범위에 포함되는지
- **[확인 필요]** 검색어 원문이 개인정보 또는 민감정보를 포함할 때의 보관·노출 정책

### 6.6 재방문

“다시 돌아오는가, 얼마나 자주 오는가”를 확인한다.

| 지표 | 표시 | 정의 초안 |
|---|---|---|
| D7 재방문율 | %, 직전 코호트 대비 pp | 가입 7일 후 기준 재방문 사용자 비율 |
| D30 재방문율 | %, 직전 코호트 대비 pp | 가입 30일 후 기준 재방문 사용자 비율 |
| WAU | 명, DAU와 MAU 보조 표기 | 최근 7일 활성 사용자 수 |
| 고착도 DAU/MAU | % | 일간 활성 사용자 ÷ 월간 활성 사용자 × 100 |
| 접속 빈도 분포 | 구간별 % | 최근 4주 활성 사용자 중 주 1~2회, 주 3~4회, 거의 매일 |
| 시간대별 접속 분포 | 시간대별 % | 장 시작 전, 장중, 장마감 후, 심야 |

- **[확인 필요]** 재방문의 이벤트 기준과 코호트 계산법
- **[확인 필요]** 시간대 구간의 정확한 시작·종료 시각 및 휴장일 처리

### 6.7 이용 환경

상시 모니터링보다 대응 범위를 정할 때 참고하는 값이다.

- 기기: 모바일, 데스크톱, 태블릿
- 운영체제: iOS, Android, Windows, macOS
- 해상도: 상위 4개 해상도와 비중
- **[확인 필요]** 기타 항목 묶음 기준과 개인정보·지문정보 관점의 보관 범위

### 6.8 데이터 소스와 품질

- **[제안]** 가입·회원·플랜 데이터는 서비스 DB, 행동·세션·환경 데이터는 GA4 또는 분석 이벤트 저장소를 기준으로 한다.
- **[제안]** 각 카드에 최종 집계 시각과 데이터 지연 여부를 표시한다.
- **[확인 필요]** GA4와 내부 DB 사용자 식별자를 연결하는 방식
- **[확인 필요]** 봇, 관리자, 테스트 계정 제외 기준
- **[확인 필요]** 지표별 원천 데이터와 집계 배치 주기

### 6.9 서비스 현황 CSV

- **[확정]** 선택 기간의 대시보드 데이터를 CSV로 다운로드한다.
- **[제안]** 화면 카드별 요약 지표와 분포 데이터를 구분할 수 있도록 `section`, `metric`, `dimension`, `value`, `unit`, `periodStart`, `periodEnd` 형태의 long format을 사용한다.
- **[확인 필요]** 화면 전체를 단일 CSV로 받을지 지표 영역별 파일 또는 ZIP으로 받을지

## 7. 회원관리 목록

### 7.1 화면 목적

회원의 가입·플랜·상태를 조건별로 조회하고, 상세 화면 진입, 일괄 상태 변경, CSV 다운로드를 수행한다.

### 7.2 조회 조건

| 조건 | 값 |
|---|---|
| 가입기간 | 시작일 ~ 종료일 |
| 가입경로 | 전체, LOCAL, KAKAO, NAVER |
| 플랜 | 전체, Free, Basic, Pro, Premium |
| 상태 | 전체, Active, Inactive, 휴면, 정지 |
| 검색 | ID, 이메일, 이름, 전화번호의 정확 또는 부분 일치 |
| 삭제 계정 포함 | 체크박스 |

- 검색은 DB의 원본 값으로 수행한다.
- 검색 결과의 개인정보는 마스킹 상태를 유지한다.
- **[제안]** 이메일은 대소문자를 구분하지 않고, 전화번호는 하이픈 유무를 정규화해 검색한다.
- **[확인 필요]** 검색 실행 방식(Enter/버튼/입력 디바운스)과 최소 검색어 길이
- **[확인 필요]** `Inactive`, `휴면`, `정지`, `삭제`의 정확한 의미와 우선순위

### 7.3 목록 컬럼

| 컬럼 | 정책 |
|---|---|
| 선택 | 행 선택 및 전체 선택 |
| ID | 원문 표시 |
| 이메일 | 마스킹 표시 |
| 이름 | 마스킹 표시 |
| 전화번호 | 마스킹 표시 |
| 가입경로 | LOCAL/KAKAO/NAVER |
| 플랜 | Free/Basic/Pro/Premium |
| 상태 | Active/Inactive/휴면/정지 |
| 가입일 | `yyyy-MM-dd HH:mm:ss` |
| 탈퇴일 | 삭제 계정 포함 조회 시 표시 **[확인 필요: 상시 컬럼 여부]** |

- 가입일은 정렬할 수 있다.
- 행을 클릭하면 회원 상세로 이동한다. **[제안]** 체크박스와 행 액션 클릭은 상세 이동에서 제외한다.
- 페이지 크기를 선택하고 총 건수와 페이지네이션을 표시한다.
- **[확인 필요]** 기본 정렬, 지원 정렬 컬럼, 페이지 크기 옵션

### 7.4 일괄 상태 변경

- **[확정]** 선택한 회원에 대해 일괄 상태 변경을 제공한다.
- **[제안]** 단건 상태 변경과 동일하게 변경 상태와 사유를 필수로 입력한다.
- **[제안]** 대상 수, 제외 수, 성공 수, 실패 수를 결과로 표시하고 부분 실패 내역을 내려받을 수 있게 한다.
- **[확인 필요]** 일괄 변경 가능한 상태와 최대 인원

### 7.5 회원 CSV

- **[확정]** 전체 선택 또는 일부 행 선택 후 다운로드한다.
- **[확정]** 포함 컬럼은 ID, 이메일, 이름, 전화번호, 가입경로, 플랜, 상태, 가입일이며 삭제 계정 조회 시 탈퇴일을 추가한다.
- **[확정]** 이메일, 이름, 전화번호는 화면과 동일하게 마스킹한다.
- **[확인 필요]** 선택이 없을 때 현재 페이지를 받을지 전체 검색 결과를 받을지

## 8. 회원 상세

### 8.1 진입과 헤더

- 회원 목록에서 진입한다.
- 헤더에 이름, ID, 현재 상태를 표시한다.
- 제공 액션: 플랜 변경, 상태 변경, 비밀번호 초기화, 정보 수정
- **[제안]** 삭제 계정에는 허용 가능한 액션만 활성화한다.

### 8.2 기본정보

| 항목 | 기본 표시 |
|---|---|
| 이메일 | 마스킹 |
| 전화번호 | 마스킹 |
| 가입경로 | 원문 |
| 가입일 | 일시 |
| 최근 접속일 | 일시 |
| 마케팅 수신 | 동의 여부와 동의/변경 일시 |

- **[확정]** 기본정보 영역에서 마스킹 해제를 제공한다.
- **[확인 필요]** 이름을 기본정보에도 별도 표시할지
- **[확인 필요]** 이메일·전화번호 외 어떤 항목까지 해제 대상으로 볼지

### 8.3 활동 요약

- **[확정]** 최근 30일 기준으로 표시한다.
- 접속일수
- 필터 적용 횟수
- 저장한 필터 수
- 관심 종목 수
- **[확인 필요]** 접속일수의 기준 이벤트와 저장·삭제 항목의 집계 시점

### 8.4 로그인 이력

- **[확정]** 최근 5건을 표시한다.
- 일시, 로그인 경로, IP, 기기/OS를 표시한다.
- **[확정]** IP는 마스킹하여 표시한다.
- **[제안]** 로그인 성공 이력과 실패 이력을 구분한다.
- **[확인 필요]** IP 마스킹 규칙, 이력 전체 보기 제공 여부, 보관 기간

### 8.5 플랜 이력

- 현재 및 과거 플랜 변경 이력을 시간순으로 표시한다.
- 플랜, 적용 기간, 변경 유형 또는 부여 사유, 변경 시각을 표시한다.
- **[제안]** 관리자 변경, 결제, 프로모션, 시스템 변경을 원인으로 구분한다.

### 8.6 운영 감사 로그

- 해당 회원에 대한 관리자 조치 이력을 최신순으로 표시한다.
- 화면 예시: 개인정보 마스킹 해제, 회원 상세 조회, 플랜 변경
- 일시, 관리자, 행위, 사유, 변경 결과를 표시한다.
- **[제안]** 개인정보 원문은 표시하거나 저장하지 않는다.

## 9. 회원 운영 액션

### 9.1 개인정보 마스킹 해제

- 회원 상세 화면에서만 가능하다.
- 사유 입력은 필수다.
- 관리자, 시각, 대상 회원, 사유, 열람 항목, 성공 여부를 감사 로그에 기록한다.
- 감사 로그 기록에 성공한 뒤에만 서버가 원문을 응답한다.
- 목록, 검색 결과, CSV에서는 해제할 수 없다.
- **[제안]** 화면 이탈·새로고침·다른 회원 이동 시 즉시 다시 마스킹하고, 같은 화면에서도 5분 후 자동 재마스킹한다.
- **[제안]** 필요한 필드만 선택해서 해제한다.
- **[확인 필요]** 해제 가능 관리자 권한, 사유 글자 수, 자동 재마스킹 시간

### 9.2 플랜 변경

입력값:

- 현재 플랜(읽기 전용)
- 변경할 플랜(필수)
- 시작일(필수)
- 만료일(필수)
- 사유(필수)

동작:

- 취소 시 변경 없이 닫는다.
- 변경 시 필수값과 기간을 검증하고 플랜 변경 이력과 운영 감사 로그를 기록한다.
- **[확정]** 화면 안내상 변경 플랜은 다음 결제일부터 적용되고 그전까지 현재 플랜을 유지한다.

**[중요 확인 필요]** 관리자 지정 시작일과 “다음 결제일부터 적용” 규칙이 충돌한다. 다음 중 하나로 명확히 해야 한다.

1. 예약 변경: 시작일에 적용하되 유료 구독 회원은 다음 결제일만 선택 가능
2. 즉시 변경: 즉시 권한을 변경하고 결제 차액을 별도 정산
3. 운영 부여: 결제와 무관한 수동 플랜 기간을 추가

추가 확인 사항:

- 업그레이드·다운그레이드의 일할 계산 및 환불
- 기존 구독과 관리자 부여 플랜의 우선순위
- 기간 중복, 조기 종료, 만료 후 복귀 플랜
- 같은 플랜으로 변경 허용 여부

### 9.3 상태 변경

입력값:

- 현재 상태(읽기 전용)
- 변경할 상태(필수)
- 상태 변경 사유(필수)

동작:

- Active 변경 시 계정을 즉시 활성화한다.
- Inactive 변경 시 계정을 즉시 비활성화하고 로그인을 차단하며 모든 세션을 만료한다.
- 변경 성공 시 운영 감사 로그를 기록한다.
- **[확정]** 비활성 계정이 휴면 또는 정지 상태일 수 있으므로 결제 내역에 대한 환불 처리가 별도로 필요하다는 주석이 있다.

확인 사항:

- **[확인 필요]** Inactive와 휴면·정지의 관계 및 상태 전이표
- **[확인 필요]** 상태별 로그인, 읽기, 결제, 환불, 데이터 보존 정책
- **[확인 필요]** 활성화 시 기존 세션 복구 여부와 재로그인 강제 여부
- **[확인 필요]** 유료 회원 정지·비활성화 시 자동 결제 중단과 환불 처리 주체

### 9.4 비밀번호 재설정

- **[확정]** 회원의 마스킹된 이메일을 안내 문구에 표시한다.
- 취소 시 변경 없이 닫는다.
- 발송 시 팝업을 닫고 비밀번호 재설정 링크를 이메일로 보낸다.
- 회원이 링크로 새 비밀번호를 설정할 때까지 기존 비밀번호는 유지된다.
- 관리자는 비밀번호를 확인할 수 없다.
- **[제안]** 재설정 토큰은 1회용이며 만료 시간을 둔다.
- **[제안]** 메일 발송 여부와 결과를 운영 감사 로그에 기록하되 토큰은 기록하지 않는다.
- **[확인 필요]** 토큰 유효시간, 재발송 제한, 기존 토큰 무효화 정책

> 화면 제목의 “비밀번호 초기화”는 실제로 임시 비밀번호를 설정하는 기능이 아니라 재설정 링크 발송이다. 기능명은 “비밀번호 재설정 메일 발송”으로 바꾸는 것이 정확하다.

### 9.5 회원정보 수정

- **[확정]** 상세 화면에 정보 수정 액션이 있다.
- **[확인 필요]** 수정 가능한 필드와 필드별 검증·중복 정책
- **[제안]** ID, 가입경로, 가입일은 수정 불가로 한다.
- **[제안]** 이메일, 이름, 전화번호는 명시적으로 변경한 필드만 서버에 전송한다.
- **[제안]** 변경 사유를 필수로 받고 변경 전·후 값을 감사 로그에 저장하되 개인정보는 마스킹 또는 암호화한다.
- **[제안]** 마스킹 문자열을 입력값으로 저장하지 못하도록 서버에서 차단한다.

## 10. 개인정보 마스킹 정책

### 10.1 적용 범위

- 회원관리 목록
- 회원 상세 기본정보
- 검색 결과
- 삭제 계정 포함 조회 결과
- CSV 다운로드
- 관리자 API와 그 밖의 백오피스 개인정보 출력 영역

원본은 DB에만 저장하고 일반 관리자 API는 서버에서 마스킹한 뒤 응답한다. 프론트엔드가 원문을 받은 뒤 숨기는 방식은 사용하지 않는다.

### 10.2 이메일

- `@` 앞 로컬 파트는 앞 4자만 노출하고 나머지를 문자 수만큼 `*`로 바꾼다.
- 도메인은 그대로 노출한다.

| 원본 | 결과 |
|---|---|
| `ttaerin92@gmail.com` | `ttae*****@gmail.com` |
| `user@example.com` | `user@example.com` |

- **[확인 필요]** 로컬 파트가 4자 이하이면 전부 노출되는 현재 규칙이 의도한 것인지
- **[제안]** 길이와 관계없이 최소 1자는 마스킹한다.

### 10.3 이름

- 3자 이상 한 단어 이름: 첫 글자와 마지막 글자만 노출하고 가운데를 `*`로 바꾼다.
- 2자 이름: 첫 글자만 노출한다.
- 영어 이름: 단어마다 첫 글자만 노출하고 나머지를 `*`로 바꾼다.

| 원본 | 결과 |
|---|---|
| `이태린` | `이*린` |
| `남궁민수` | `남**수` |
| `이린` | `이*` |
| `Taerin Lee` | `T***** L**` |

- **[확인 필요]** 1자 이름, 공백이 있는 한글 이름, 하이픈·아포스트로피 이름 처리
- **[제안]** 언어 판별 대신 공백으로 나눈 각 단어에 같은 규칙을 적용한다.

### 10.4 전화번호

- 첫 구간과 마지막 구간은 노출하고 가운데 구간의 숫자를 모두 `*`로 바꾼다.

| 원본 | 결과 |
|---|---|
| `010-1234-5678` | `010-****-5678` |
| `02-123-4567` | `02-***-4567` |

- **[확인 필요]** 하이픈 없는 번호, 국제번호, 대표번호 처리
- **[제안]** 저장 시 정규화된 숫자를 기준으로 형식을 판별한 뒤 마스킹하고 원래 구분 형식은 표시 계층에서 통일한다.

### 10.5 검색과 CSV

- 원본 전체 또는 일부 값으로 검색할 수 있다.
- 검색 결과는 계속 마스킹한다.
- CSV에도 화면과 같은 공통 서버 마스킹 함수를 적용한다.
- 검색어가 서버, 프록시, APM, 브라우저 로그에 평문으로 남지 않게 한다.

## 11. 상태 모델 초안

첨부 화면에는 Active, Inactive, 휴면, 정지, 삭제 계정이 함께 등장하지만 관계가 정의되어 있지 않다. 구현 전 아래 모델 중 하나를 선택해야 한다.

### 권장안: 계정 상태와 삭제 상태 분리

- `accountStatus`: ACTIVE / INACTIVE / DORMANT / SUSPENDED
- `deletedAt`: 탈퇴 또는 삭제 여부

장점은 휴면·정지·비활성과 탈퇴를 독립적으로 관리할 수 있고 `삭제 계정 포함` 조회도 명확해진다는 점이다.

| 현재 상태 | 가능한 변경 | 핵심 효과 초안 |
|---|---|---|
| ACTIVE | INACTIVE, DORMANT, SUSPENDED | 상태별 제한 적용 |
| INACTIVE | ACTIVE | 재활성화 시 재로그인 |
| DORMANT | ACTIVE | 휴면 해제 절차 적용 |
| SUSPENDED | ACTIVE, INACTIVE | 정지 사유 해소 후 변경 |
| 삭제 | **[확인 필요]** 복구 가능 여부 | 기본 조회 제외, 개인정보 마스킹 |

## 12. 예외 및 오류 처리

- 권한 없음: 기능을 숨기는 것과 별개로 서버에서 403 처리한다.
- 대상 회원 없음: 404 처리하고 개인정보 존재 여부를 과도하게 노출하지 않는다.
- 동시 변경: 최신 상태가 달라졌으면 변경을 거절하고 새로고침을 안내한다.
- 감사 로그 기록 실패: 개인정보 해제와 운영 변경은 실패 처리한다.
- CSV 생성 실패: 재시도 가능 여부와 실패 원인을 안내하고 실패 이력을 남긴다.
- 이메일 발송 실패: 재설정 요청 성공으로 표시하지 않고 재시도를 제공한다.
- 집계 지연: 서비스 현황 카드에 최종 집계 시각과 지연 상태를 표시한다.

## 13. 비기능 요구사항

### 13.1 보안

- 모든 관리자 API에 인증과 권한 검사를 적용한다.
- 개인정보 원문, 재설정 토큰, 인증정보를 애플리케이션 로그에 남기지 않는다.
- 마스킹 해제 응답에 브라우저·프록시 캐시 금지 헤더를 적용한다.
- 관리자 세션 만료와 강제 로그아웃을 지원한다.
- **[제안]** 개인정보 원문 조회와 CSV 다운로드에 속도 제한과 이상 행위 탐지를 적용한다.

### 13.2 성능

- **[제안]** 일반 목록·상세 조회는 95백분위 2초 이내를 목표로 한다.
- **[제안]** 대시보드는 사전 집계 데이터를 사용하고 95백분위 3초 이내를 목표로 한다.
- **[확인 필요]** 회원 규모, 이벤트 규모, 동시 관리자 수를 기준으로 목표를 재확정한다.

### 13.3 접근성과 사용성

- 상태는 색상뿐 아니라 텍스트로 구분한다.
- 키보드로 필터, 표, 팝업을 조작할 수 있어야 한다.
- 팝업을 닫을 때 입력 중인 내용이 있으면 확인한다.
- 파괴적 또는 접근 차단 성격의 변경은 대상과 영향을 다시 확인한다.

## 14. 수용 기준

### 14.1 서비스 현황

1. 선택 기간에 따라 모든 지표가 같은 기간 기준으로 갱신된다.
2. 비교값은 직전 동일 길이 기간 기준으로 계산된다.
3. 지표별 값, 단위, 빈 데이터, 집계 지연 상태가 구분된다.
4. CSV 값이 화면의 조회 조건 및 집계값과 일치한다.

### 14.2 회원 목록

1. 기간, 가입경로, 플랜, 상태, 삭제 포함 조건을 조합해 조회할 수 있다.
2. ID·이메일·이름·전화번호 원본의 정확 및 부분 일치 검색이 가능하다.
3. 검색 결과와 삭제 계정의 개인정보가 마스킹된다.
4. 선택 회원의 일괄 상태 변경과 CSV 다운로드가 권한에 따라 동작한다.
5. CSV 개인정보가 화면과 동일하게 마스킹된다.

### 14.3 회원 상세와 운영 액션

1. 기본정보, 최근 30일 활동, 최근 5건 로그인, 플랜 이력, 감사 로그를 조회할 수 있다.
2. 개인정보 원문은 상세 화면에서 사유를 입력한 권한자만 조회할 수 있다.
3. 마스킹 해제, 플랜 변경, 상태 변경, 재설정 메일, 정보 수정이 감사 로그에 기록된다.
4. Inactive 변경 즉시 로그인이 차단되고 기존 세션이 만료된다.
5. 비밀번호 재설정 메일 발송 전까지와 발송 후 새 비밀번호 설정 전까지 기존 비밀번호가 유지된다.
6. 마스킹 문자열이 회원 개인정보 원본으로 저장되지 않는다.

## 15. 현행 시스템 대비 주요 차이

문서 작성 시점의 저장소를 기준으로 확인한 내용이다.

- 회원 목록 API는 현재 이메일·이름·전화번호 원문을 반환한다.
- 검색은 이미 username, email, name, phone 원본의 부분 일치를 지원한다.
- 관리자 인증이 공용 API Key 방식이라 개인 단위 감사가 어렵다.
- 회원 상세 전용 API, 로그인 이력, 활동 요약, 운영 감사 로그가 없다.
- 마스킹 해제, 플랜 예약 변경, 상태 변경, 재설정 링크 발송 기능이 없다.
- CSV 다운로드 기능이 없다.
- 현재 회원 수정 UI는 목록 응답값을 폼 초기값으로 사용해 마스킹 문자열 저장 위험이 있다.
- 현재 관리자 삭제 동작은 연관 데이터를 포함한 물리 삭제이므로 `삭제 계정 포함` 요구와 충돌한다.
- 현재 비밀번호 관련 관리자 흐름은 재설정 링크 발송 기획과 다를 수 있어 통합이 필요하다.
- 서비스 현황 화면의 지표 대부분은 현재 별도 집계·분석 데이터 모델이 필요하다.

5. 비밀번호 재설정 토큰 유효시간과 재발송 제한
