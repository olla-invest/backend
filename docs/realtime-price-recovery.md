# 실시간 가격 보존 및 개발 환경 복구

## 가격 저장

체결 가격은 로컬 메모리에 즉시 반영하고, 종목별 마지막 값을 1초 단위로 Redis hash에 저장한다. 수신 시각을 Lua에서 원자적으로 비교하여 다른 인스턴스의 지연된 쓰기가 새 가격을 덮어쓰지 못하게 한다. 기동 시 복원하고 5초마다 공유 값을 읽는다. 구독 해제로 가격을 삭제하지 않는다.

기본 키는 `olla:realtime:prices:live:v1`이며 모의투자는 `olla:realtime:prices:mock:v1`으로 분리한다. `REALTIME_PRICE_REDIS_KEY`로 공급원별 키를 지정할 수 있다. 실제로 동일한 가격 공급원을 사용하는 인스턴스만 같은 키를 사용해야 한다. hash TTL은 마지막 쓰기로부터 30일이다.

Redis 연결·명령은 5초 제한을 두고 실패 시 로컬 가격을 유지한다. 미저장 체결은 다음 주기에 다시 쓰며, 응답이 정지한 연결은 폐기한 뒤 재접속한다. 상태 API는 `cache.redisKey`, `cache.pendingRedisWrites`를 제공한다. 연결 상태와 가격의 최신성은 별도로 확인해야 한다.

## 가격 선택

- 장중: 오늘 체결이며 수신 후 10분 이내인 가격을 사용한다.
- 장 종료·주말·휴장일: 최신 거래일에 받은 마지막 가격을 유지한다.
- 다음 거래일 개장 전: 직전 거래일 가격을 유지한다.
- 미래 시각·휴장일 수신으로 표시된 값·유효하지 않은 가격은 제외한다.
- 정규장(09:00~15:35 KST, 종가 단일가 체결 포함) 밖에서 받은 체결은 저장·사용하지 않는다. 16:00~18:00 시간외 단일가 체결이 정규장 종가를 덮어쓰던 문제를 막기 위함이다. 실시간 일봉 저장(`handleRealtimeCandlePersistence`)에도 같은 기준을 적용한다.

보존하는 값은 **마지막 수신 가격**이다. 확정 종가라는 의미는 아니며, 모든 종목의 종가를 확보하려면 종가 수집 배치가 필요하다. 이 변경 전 받은 메모리 가격은 소급해서 복원할 수 없다.

## 스케줄과 연결

`SCHEDULER_ENABLED=false`는 데이터·결제 배치를 중단하되 `realtime:prepare`, `realtime:reconnect`, `realtime:heartbeat` 크론을 유지한다. 개발 기동 시 대량 캔들 수집도 생략한다. `REALTIME_ENABLED=false`를 별도로 지정하면 실시간 연결과 해당 크론을 중단할 수 있다.

성공한 LOGIN 응답을 받은 소켓만 연결 상태로 표시한다. 로그인 거부 또는 10초간 응답이 없으면 소켓을 종료한다. 재연결 시 기존 구독을 복원한 뒤 누락 종목을 등록하고, 이전 소켓의 비동기 작업이 새 소켓에 등록을 보내지 못하도록 차단한다.

거래대금 스냅샷은 KRX 거래일 09:00~15:30에 유효한 가격만 저장한다. 기존 휴장일 데이터는 이 변경으로 삭제하지 않는다.
