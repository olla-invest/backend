## 개요

### 프로젝트 배경
현재 주식 실시간 차트 백엔드 시스템은 개발자 로컬 PC에서 개발 중입니다. 실제 서비스로 제공하기 위해서는 **안정적인 클라우드 환경**에서 24시간 운영되어야 합니다.

### 목표
- **24시간 무중단 서비스** 제공
- **확장 가능한 인프라** 구축으로 사용자 증가에 대응
- **데이터 안전성** 보장 (백업, 복구)
- **비용 효율적** 운영 (단계적 투자)

### 4단계 접근 전략
위험을 최소화하고 비용을 단계적으로 투자하기 위해 **4단계 배포 전략**을 수립했습니다.

| 단계 | 목적 | 예상 기간 | 예상 비용 (월) |
|------|------|-----------|----------------|
| Phase 1 | 개발/테스트 환경 구축 | 1-2주 | $50-80 |
| Phase 2 | 사전 상용 환경 (내부 테스트) | 2-4주 | $150-200 |
| Phase 3 | 제한적 오픈 (베타 서비스) | 1-3개월 | $300-400 |
| Phase 4 | 완전 상용화 | 지속 운영 | $500-800+ |

## 왜 AWS 클라우드인가?

### 현재 문제점 (로컬 PC 운영)
- ❌ 개발자 PC를 꺼면 서비스 중단
- ❌ 외부에서 접속 불가능 (고정 IP 없음)
- ❌ 하드웨어 고장 시 데이터 손실 위험
- ❌ 사용자 증가 시 확장 불가능
- ❌ 보안 취약 (개인 PC 방화벽만 의존)

### AWS 클라우드 도입 효과
- ✅ **24시간 무중단 운영**: 서버가 클라우드에서 항상 실행
- ✅ **어디서나 접속 가능**: 고정 IP 주소로 안정적 연결
- ✅ **자동 백업**: 매일 데이터 자동 백업으로 손실 방지
- ✅ **탄력적 확장**: 사용자 증가 시 서버 성능 업그레이드 가능
- ✅ **전문 보안**: AWS 글로벌 보안 인프라 활용
- ✅ **비용 효율**: 사용한 만큼만 지불 (초기 장비 구매 불필요)

### 대안 대비 AWS 선택 이유

| 구분 | 자체 서버 구축 | 다른 클라우드 | AWS |
|------|---------------|--------------|-----|
| 초기 비용 | 높음 (수백만원) | 중간 | 낮음 (월 단위) |
| 확장성 | 어려움 | 보통 | 매우 쉬움 |
| 안정성 | 낮음 | 보통 | 매우 높음 (99.99%) |
| 기술 지원 | 없음 | 보통 | 광범위 |
| 글로벌 점유율 | - | 10-20% | 32% (1위) |

## Phase 1: 개발/테스트 환경

|------|------------|------|------|---------|
| **EC2** (가상 서버) | 24시간 돌아가는 서버 필요 | 백엔드 프로그램 실행 | t3.medium (2코어/4GB RAM) | $30 |

## Phase 2: 사전 상용 환경

### 📌 목적
**내부 테스트**용 환경 (실제 서비스와 동일 구조, 소규모 사용자 대상)

### Phase 1과의 핵심 차이
- **데이터베이스**: EC2 내부 → 별도 RDS 전문 서비스 (자동 백업)
- **캐시**: EC2 내부 → 별도 ElastiCache (성능 향상)
- **백업**: 수동 → 자동 (매일 새벽)
- **복구**: 불가 → 자동 복구 가능

### 필요 항목 및 비용

| 항목 | 필요한 이유 | 역할 | 사양 | 월 비용 |
|------|------------|------|------|---------|
| **EC2** (백엔드) | Phase 1과 동일 | 백엔드 실행 | t3.medium | $30 |
| **RDS** (DB 전문서비스) | 자동 백업/복구 필요 | DB 자동 관리 (백업/업데이트) | db.t3.medium | $80 |
| **ElastiCache** (캐시) | 성능 향상 필요 | Redis 전문 관리 | cache.t3.micro | $15 |
| **저장공간** | 데이터 증가 대비 | 프로그램 + DB 저장 | 100GB | $15 |
| **백업 스토리지** | 7일치 백업 보관 | 매일 자동 백업 저장 | 50GB | $5 |
| **네트워크** | 트래픽 증가 | 데이터 송수신 | 약 150GB | $13 |
| **모니터링 (고급)** | 알람 설정 필요 | CPU/메모리 과부하 알림 | CloudWatch + 알람 | $12 |

**💰 Phase 2 총 비용: 월 $170 (약 ₩226,100)**

### 🆕 추가 기능
- ✅ **자동 백업**: 매일 새벽 3시 전체 DB 백업 (7일 보관)
- ✅ **복구 가능**: 특정 시점으로 복구 (Point-in-Time Recovery)
- ✅ **HTTPS 적용**: SSL 인증서로 암호화 통신
- ✅ **자동 알람**: CPU/메모리 과부하 시 개발자에게 알림

### ⚠️ 제약사항
- 여전히 단일 EC2 서버 (백엔드 고장 시 중단)
- 내부 테스트 전용 (공개 서비스 아님)

### ✅ 다음 단계 진행 조건
- 1개월 안정 운영 (가동률 99% 이상)
- 내부 팀원 10-20명 테스트 통과
- 베타 서비스 승인 및 Phase 3 예산 확보

## Phase 3: 제한적 상용 서비스 (베타)

### 📌 목적
**소규모 실제 사용자** (100-500명) 대상 베타 서비스 오픈 + 자동 확장 기능

- **장애 대응**: 수동 → 자동 복구
- **데이터베이스**: 단일 → 이중화 (Multi-AZ)
- **사용자**: 내부 10-20명 → 외부 100-500명

| 항목 | 필요한 이유 | 역할 | 사양 | 월 비용 |

- ✅ **무중단 서비스**: 서버 1대 고장 시 자동으로 다른 서버로 연결
