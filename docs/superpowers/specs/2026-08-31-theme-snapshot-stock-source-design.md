# 종목 스냅샷 기반 테마 집계 설계

## 1. 목적

이슈 테마, 내 관심, 추천 화면이 동일한 거래일에도 서로 다른 테마 순위와 종목 수를 반환하는 문제를 해결한다.

테마 데이터는 화면에 필요한 형태로 가공할 수 있지만, 모든 가공의 종목 원본은 하나의 확정된 종목 종가·순위 스냅샷으로 제한한다. 테마 서비스가 실시간 가격 캐시와 `stock_daily_metrics`를 다시 조합하거나 별도의 적격 종목 집합을 계산하지 못하게 한다.

## 2. 단일 원본

테마 집계의 유일한 종목 원본은 `stock_current_rank_snapshots`이다.

하나의 테마 스냅샷은 반드시 동일한 다음 키를 가진 종목 스냅샷 행들로만 생성한다.

- `trade_date`
- `snapshot_time`

테마 스냅샷 생성 시 다른 시각이나 다른 거래일의 종목 행을 섞지 않는다. 종목과 테마의 관계를 확인하기 위한 `stock_themes` 및 테마 메타데이터 조회는 허용하지만, 가격·RS·필터·등락 정보는 다른 테이블에서 보충하지 않는다.

## 3. 종목 스냅샷 보강

현재 `stock_current_rank_snapshots`에는 다음 값이 있다.

- 종목 코드
- 거래일 및 스냅샷 시각
- 현재 순위와 RS 점수
- 현재가와 기준 종가
- 동적 필터 값 및 통과 여부
- 가격 출처

테마 집계에 필요한 다음 필드를 추가한다.

- `price_change_rate`: 스냅샷 시점의 기준 종가 대비 등락률
- `trading_value`: 스냅샷 시점 누적 거래대금 또는 확정 거래대금
- `previous_trading_value_ratio`: 전일 동일 시각 또는 전일 확정 거래대금 대비 비율
- `is_new_high`: 해당 스냅샷 가격 기준 신고가 여부

등락률은 스냅샷 생성 시 한 번 계산해 저장한다. 테마 서비스가 `current_price`와 `close_price`로 다시 계산하지 않는다. 실시간 가격 사용 여부와 종가 폴백은 기존 `CurrentPriceResolver`의 판정을 따른다.

장중에는 신선한 실시간 데이터가 있으면 현재가·등락률·누적 거래대금을 사용한다. 유효한 실시간 데이터가 없거나 장 마감 후에는 해당 거래일의 확정 일별 값으로 종목 스냅샷을 생성한다.

## 4. 테마 스냅샷 생성

테마 스냅샷 생성기는 대상 거래일의 최신 종목 스냅샷 시각을 한 번 선택한다. 선택한 시각에 `passed_dynamic_filters = true`이고 `current_rank IS NOT NULL`인 종목만 집계한다.

종목 집합에 `stock_themes`의 활성 네이버 테마 매핑을 결합하고 테마별로 다음 값을 계산한다.

- `total_count`: 포함된 고유 종목 수
- `rising_count`: `price_change_rate > 0`인 종목 수
- `up_count`: `price_change_rate > 0`인 종목 수
- `down_count`: `price_change_rate < 0`인 종목 수
- `flat_count`: `price_change_rate = 0`인 종목 수
- `rising_ratio`: 상승 종목 수 / 전체 종목 수
- `avg_change_rate`: 평균 등락률
- `avg_rs_score`: 평균 RS 점수
- `new_high_count`: 신고가 종목 수
- `high_volume_count`: `previous_trading_value_ratio >= 2`인 종목 수

테마 노출 기준은 최소 한 종목이다. RS 80 이상 종목만 별도로 제한하지 않는다. RS 80은 요청 필터이며 기본 테마 집계의 종목 적격 조건이 아니다.

테마 현재 순위는 이슈 테마 기본 목록과 동일하게 `avg_rs_score DESC`, `avg_change_rate DESC`, `theme_code ASC` 순서로 결정한다. 동점 처리 규칙은 API 응답의 현재 정렬 규칙과 동일하게 순차 순위를 사용한다.

## 5. 원본 추적성

`theme_daily_snapshots`에 다음 필드를 추가한다.

- `stock_snapshot_time`: 집계에 사용한 종목 스냅샷 시각

`snapshot_date + stock_snapshot_time`으로 어떤 종목 상태에서 테마 값이 만들어졌는지 추적할 수 있어야 한다. 동일 거래일 재생성은 upsert로 동일 결과를 만든다.

## 6. API 사용 규칙

다음 API는 현재 테마 순위와 집계 수치를 자체 계산하지 않고 최신 유효 테마 스냅샷에서 읽는다.

- 이슈 테마 목록
- 이슈 테마 상세 헤더
- 내 관심 테마
- 함께 보면 좋은 테마 추천

테마 상세의 종목 행은 테마 스냅샷의 `stock_snapshot_time`과 동일한 종목 스냅샷에서 조회한다. 정렬과 표시 개수는 요청에 맞게 가공할 수 있지만 종목 적격 여부와 가격·RS·등락률은 변경하지 않는다.

전일 대비 순위는 현재 스냅샷보다 이전 거래일의 최신 확정 테마 스냅샷과 비교한다.

응답 필드명과 타입은 유지한다. 기존 클라이언트 계약을 변경하지 않는다.

## 7. 배치 순서

장 마감 배치 순서를 다음과 같이 고정한다.

1. 당일 종가와 지수 캔들 수집
2. 당일 종목 메트릭 계산
3. 당일 확정 종목 종가·순위 스냅샷 생성
4. 종목 일별 `current_rank` 확정
5. 동일 종목 스냅샷을 원본으로 테마 스냅샷 생성
6. 테마 AI 요약 등 후속 작업 실행

3단계가 실패하거나 대상 종목 스냅샷이 비어 있으면 5단계를 실행하지 않는다. 전일 종목 스냅샷을 당일 테마 스냅샷 원본으로 대체하지 않는다.

장중 테마 갱신이 필요하면 최신 10분 종목 스냅샷을 원본으로 별도의 장중 테마 조회를 만들 수 있다. 이번 변경에서는 일별 확정 테마 스냅샷을 우선 단일화하며, API가 요청 시 실시간 캐시로 테마를 다시 계산하는 동작은 제거한다.

## 8. 백필

기존 `stock_current_rank_snapshots`에 새 필드가 없는 과거 데이터는 `stock_daily_metrics`를 직접 읽어 테마만 재계산하지 않는다.

백필은 거래일별로 다음 순서를 따른다.

1. 해당 거래일의 확정 종목 스냅샷을 새 스키마로 재생성
2. 생성된 종목 스냅샷의 최신 시각을 선택
3. 동일 원본으로 테마 스냅샷 재생성

필요한 종목 원본을 복원할 수 없는 거래일은 건너뛰고 원인을 로그에 남긴다. 부분 데이터로 정상 스냅샷처럼 저장하지 않는다.

## 9. 마이그레이션

마이그레이션은 새 컬럼을 우선 nullable로 추가한다.

- `stock_current_rank_snapshots.price_change_rate`
- `stock_current_rank_snapshots.trading_value`
- `stock_current_rank_snapshots.previous_trading_value_ratio`
- `stock_current_rank_snapshots.is_new_high`
- `theme_daily_snapshots.stock_snapshot_time`

새 생성 경로가 모든 필드를 채우도록 배포한 뒤 백필한다. 과거 데이터 검증이 끝나기 전에는 데이터베이스 NOT NULL 제약을 추가하지 않는다.

## 10. 오류 처리와 관측성

다음을 구조화 로그로 기록한다.

- 선택한 `trade_date`와 `snapshot_time`
- 종목 스냅샷 전체 행 수와 적격 행 수
- 테마 매핑 종목 수와 생성된 테마 수
- 테마 스냅샷별 `stock_snapshot_time`
- 필수 필드가 없어 제외된 종목 수
- 종목 스냅샷 부재로 건너뛴 테마 배치

테마 API는 원본이 불완전할 때 다른 데이터 소스로 즉석 폴백하지 않는다. 최신 완전한 테마 스냅샷을 반환하거나, 스냅샷이 전혀 없으면 기존 빈 응답 계약을 따른다.

## 11. 테스트 전략

### 종목 스냅샷

- 실시간가 사용 시 등락률·거래대금·신고가 값 저장
- 종가 폴백 시 일별 확정 값 저장
- 같은 거래일과 시각 재실행 결과 동일

### 테마 집계

- 하나의 `trade_date + snapshot_time`만 사용
- 동적 필터 미통과 종목 제외
- RS 80 미만이더라도 적격 종목이면 포함
- 상승·보합·하락 합이 전체 종목 수와 일치
- 평균 RS와 테마 순위가 이슈 테마 목록 기준과 일치
- 다른 시각의 종목 행이 섞이지 않음

### API 회귀

- OLED 추천 카드와 이슈 테마 상세의 현재 순위 일치
- OLED 추천 카드와 상세의 전체·상승·보합·하락 수 일치
- 내 관심, 추천, 이슈 테마 목록이 동일 테마 스냅샷 사용
- 응답 필드와 타입 유지

### 배치

- 종목 스냅샷 이후 테마 스냅샷 실행
- 종목 스냅샷 실패 시 테마 스냅샷 미실행
- 백필이 종목 스냅샷을 먼저 재생성

## 12. 완료 기준

- 테마 집계가 가격 캐시와 `stock_daily_metrics`를 직접 읽지 않는다.
- 모든 테마 집계 행이 원본 `stock_snapshot_time`을 가진다.
- 이슈 테마, 내 관심, 추천, 상세가 동일한 현재 순위와 종목 수를 반환한다.
- 동일 거래일 재실행 결과가 동일하다.
- OLED 사례의 `4위/3종목`과 `34위/7종목` 불일치가 재발하지 않는다.
- 관련 단위 테스트, 통합 테스트 및 Nest 빌드가 통과한다.
